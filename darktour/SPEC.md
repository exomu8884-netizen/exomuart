# 다크투어 — 설계 명세 (v1)

> 역사 속 소수자의 자리만 골라 걷는 관광 코스 앱.
> exomu.art 의 하위 경로 `/darktour/` 에 얹는 완전 정적 웹앱.

---

## 0. 한 줄 정의

관광지가 아니라 **"여기서 누가 지워졌는가"** 를 색인하는 앱.
관광공사 API는 주소·사진·좌표만 제공하고, **이야기는 우리가 쓰고 한국민족문화대백과사전이 뒷받침한다.**

---

## 1. 사용자 흐름

```
① 광역시도 선택 (17개)
        ↓
② 시군구 선택            ← TourAPI 는 여기서부터 개입
        ↓
③ 렌즈 선택 — 「누구의 눈으로 볼까요?」 (여러 개 선택 가능 · 합집합)
   민중 / 여성 / 장애인 / 성소수자 / 청소년
   여러 개 고르면 각 렌즈의 자리가 모두 코스에 들어온다 (교집합 아님)
        ↓
④ 기간 선택  반나절 · 하루 · 1박2일
        ↓
⑤ 코스 2안 제시
   A안 「시간의 길」 — 사건 연대순
   B안 「발의 길」   — 도보·이동 최적순
        ↓
⑥ 코스 상세: 지도(Leaflet+OSM) + 정거장별 이야기 + 방문 예절
```

UI 문구는 **"누구의 눈으로 볼까요?"**, 내부 필드명은 `lens`.
("계급"은 민중에는 맞지만 여성·장애인·성소수자에는 맞지 않아 배제.)

## 2. 비용 설계 — 여기가 이 앱의 뼈대

한 번 만든 건 다시 만들지 않는다. 세 가지 규칙으로 호출량을 억제한다.

### 규칙 1 — 캐시 키에서 '기간'을 뺀다

기간은 **생성이 아니라 조립**이다. 한 번 부를 때 정거장 풀 6~8곳을 통째로 만들고,
기간은 클라이언트가 자르기만 한다.

| 기간 | 정거장 수 |
|---|---|
| 반나절 | 상위 3곳 |
| 하루 | 5곳 |
| 1박2일 | 8곳 (Day1 / Day2 분할) |

| 캐시 단위 | 조합 수 | 판정 |
|---|---|---|
| 시도 × 렌즈 × 기간 | 17 × 5 × 3 = 255 | ✗ |
| **시도 × 렌즈** | **17 × 5 = 85** | ✓ 채택 |

### 규칙 2 — 캐시 키에서 '렌즈 조합'을 뺀다

조합을 전부 캐시하면 `(2⁵−1) × 17 = 527건`으로 터진다.
캐시는 **단일 렌즈로만** 굽고, 다중 선택은 브라우저에서 **합집합**으로 합친다.

```
사용자가 [여성] + [청소년] 선택
  → 36__women.json, 36__youth.json 두 파일 로드
  → 두 풀을 합집합으로 병합 (여성 자리 전부 + 청소년 자리 전부)
  → place.id 로 중복 제거, lensNotes 는 병합
  → LLM 호출 0회
```

**합집합이 기본이자 유일한 병합 규칙이다.** 교집합(둘 다 해당하는 곳만) 필터는 두지 않는다 —
결과가 거의 비고, 렌즈를 더 고를수록 볼 게 줄어드는 건 이 앱의 의도와 반대다.
여러 렌즈가 붙은 장소는 필터가 아니라 표시로 다룬다: 배지가 여러 개 달리고 `lensNotes` 가 여러 문단 뜬다.

### 규칙 3 — TourAPI 는 시군구 확정 후 1회, 결과는 영구 캐시

광역시도만으로 `searchKeyword2` 를 때리면 동명 지명 오매칭이 심하다.
`areaCode` + `sigunguCode` 로 좁힌 뒤 매칭한다. 한 번 조회한 키워드는 재조회하지 않는다.

### 규칙 4 — 캐시 저장소 = 이 깃 레포

```
darktour/data/cache/36__women.json      ← 경남 × 여성
darktour/data/cache/11__lgbtq.json      ← 서울 × 성소수자
```

방문자 입장에서는 **API 호출 0원, 서버 0대, 로딩 즉시.**
새 지역이 필요하면 운영자가 Claude Code 에게 요청 → 생성 → 커밋. 캐시가 곧 깃 히스토리.

> 확장 여지: 앱은 `resolveCourse(sido, sigungu, lenses, days)` 함수 하나로만 코스를 가져온다.
> 훗날 Cloudflare Workers 를 붙일 때 이 함수의 캐시 미스 분기만 교체하면 된다.

## 3. 데이터 모델

### 3.1 `data/regions.json` — 지역 + TourAPI 코드

```jsonc
{
  "sido": [
    { "areaCode": 36, "name": "경상남도", "short": "경남",
      "sigungu": [ { "code": 12, "name": "진주시" }, ... ] }
  ]
}
```
TourAPI `areaCode2` 응답을 그대로 굳혀둔 것. 빌드 스크립트가 갱신한다.

### 3.2 `data/lenses.json` — 렌즈 정의

```jsonc
{ "lenses": [
  { "id": "people",     "label": "민중",     "color": "#c9a06a",
    "blurb": "이름이 기록되지 않은 채 일하고, 싸우고, 돌을 새긴 사람들." },
  { "id": "women",      "label": "여성",     "color": "#d98a9b", "blurb": "..." },
  { "id": "disability", "label": "장애인",   "color": "#6fb0c9", "blurb": "..." },
  { "id": "lgbtq",      "label": "성소수자", "color": "#a98ad9", "blurb": "..." },
  { "id": "youth",      "label": "청소년",   "color": "#7fb98a", "blurb": "..." }
] }
```

### 3.3 `data/cache/{areaCode}__{lens}.json` — 생성 캐시 (85개)

```jsonc
{
  "areaCode": 36,
  "lens": "women",
  "generatedAt": "2026-07-28",
  "generator": "claude-code",

  "places": [
    {
      "id": "jinju-hyeongpyeong",          // 전역 고유. 합집합 병합 시 중복 제거 키
      "name": "형평운동기념탑",
      "sigunguCode": 12,
      "sigungu": "진주시",
      "lenses": ["people", "women"],        // 이 장소가 걸치는 렌즈 전부
      "era": "1923",
      "eraStart": 1923,                     // ★ 정렬용 숫자. 「시간의 길」 순서를 계산한다
      "weight": 3,                          // ★ 1~3. 기간이 짧을 때 무엇을 남길지
      "evidence": "record",                 // ★ record 사료 | site 유물·유적 | oral 구술 | legend 설화
      "lat": 35.19, "lng": 128.08,
      "coordAccuracy": "approx",            // approx | tourapi | verified

      "voices": "백정 — 신분 폐지 후에도 호적에 붉은 점이 찍히던 사람들",
      "summary": "한 줄 요약",
      "story": ["문단1", "문단2", "문단3"],

      "lensNotes": {                        // 렌즈별 한 문단. 교차 시 함께 노출
        "people": "...",
        "women":  "..."
      },

      "ethics": "추모 공간이다. 인증샷보다 묵념을.",
      "visit":  "상시 개방 · 무료",
      "caution": null,                      // 거주민 있음 / 출입 제한 등

      "tourKeyword": "형평운동기념탑",       // TourAPI 매칭용
      "encyQuery":   "형평사",               // 백과사전 검색어

      "sources": [                          // ★ 필수. 비어 있으면 그 장소는 싣지 않는다
        { "type": "문헌", "label": "형평사 창립 취지문(1923)" },
        { "type": "사전", "label": "한국민족문화대백과사전 «형평사»", "encyQuery": "형평사" },
        { "type": "기관", "label": "형평운동기념사업회" }
      ],
      "sourceNote": null,                   // 출처를 밝힐 수 없는 이유가 있을 때만
      "links": []
    }
  ],

  "regionNote": "진주는 조선의 신분제가 가장 늦게까지 살아남은 곳이자, 그것을 가장 먼저 공개적으로 거부한 곳이다."

```

### 순서는 저장하지 않고 계산한다

합집합이 기본이 되면 "렌즈 A 파일의 순서"와 "렌즈 B 파일의 순서"를 합칠 방법이 없다.
그래서 순서를 캐시에 박아두지 않고, 병합된 풀에서 **매번 계산**한다.

| 안 | 정렬 규칙 | 근거 필드 |
|---|---|---|
| **A안 「시간의 길」** | `eraStart` 오름차순 | 어떤 렌즈 조합이든 연대순은 항상 정의된다 |
| **B안 「발의 길」** | 첫 정거장에서 최근접 이웃 탐색 | `lat`/`lng` 만 있으면 된다 |

정거장이 3~8개뿐이라 최근접 이웃으로 충분하고, 렌즈를 몇 개 고르든 같은 규칙이 동작한다.

### 기간 슬라이스 — 렌즈별 최소 1곳 보장

병합된 풀이 기간 정원을 넘으면 잘라내야 한다. 이때 단순히 `weight` 내림차순으로 자르면
**선택한 렌즈 하나가 코스에서 통째로 사라질 수 있다** (성소수자를 골랐는데 한 곳도 안 나오는 상황).
그래서 3단계로 뽑는다.

```
하루(5곳) · [민중][여성][청소년] 선택
  1단계  선택한 각 렌즈에서 weight 최고 1곳씩 먼저 확보   → 3곳
  2단계  남은 2자리를 전체 풀의 weight 내림차순으로 채움   → 5곳
  3단계  확정된 5곳을 eraStart(A안) 또는 좌표(B안) 순으로 배열
```

즉 **누가 반드시 들어갈지는 렌즈 쿼터, 나머지를 무엇으로 채울지는 `weight`,
어떤 순서로 볼지는 `eraStart`/좌표**가 정한다.

**정원 < 렌즈 수인 경우** (반나절 3곳에 렌즈 5개 선택) 는 쿼터를 다 채울 수 없다.
조용히 버리지 않고 사용자에게 알린다.

> 반나절로는 5개 관점을 다 담을 수 없어요.
> [하루로 늘리기] [렌즈 줄이기] [이대로 보기 — 3개 관점만 나옵니다]

### 코스 소개문

A안/B안의 설명문은 캐시가 아니라 앱의 고정 문구다 (합집합에서 충돌하지 않도록).
지역·렌즈 고유의 맥락은 캐시의 `regionNote` 가 담고, 여러 렌즈를 고르면 선택한 렌즈들의 `regionNote` 가 나란히 뜬다.

**설계 의도**
- `places` 는 풀(pool)이지 코스가 아니다. 코스는 `orders` × 기간 슬라이스로 만들어진다.
- 같은 장소가 여러 렌즈 캐시에 중복 등장하는 것은 정상. 합집합 병합 시 `id` 로 중복을 제거하고 `lensNotes` 는 합친다.
- `story` 는 렌즈 무관 공통 서사, `lensNotes` 는 렌즈별 관점. 이 분리 덕분에 한 장소를 여러 렌즈로 겹쳐 읽을 수 있다.
- 정거장 수가 기간을 넘치면 `orders` 순서대로 앞에서부터 자른다. 렌즈를 여러 개 골라도 코스 길이는 기간이 결정한다.

### 3.4 근거와 출처

**모든 장소에 출처를 단다. 출처가 없는 글은 싣지 않는다.**

근거의 성격이 다르면 독자가 다르게 읽어야 하므로, 장소마다 `evidence` 로 층위를 밝힌다.

| `evidence` | 화면 표기 | 뜻 |
|---|---|---|
| `record` | 사료 기록 | 문헌·법령·판례 등 문서로 남은 사실 |
| `site` | 유물·유적 | 남아 있는 건물·유물 자체가 근거 |
| `oral` | 구술·증언 | 당사자·관계자의 증언. 세부는 증언마다 다를 수 있음 |
| `legend` | 전해지는 이야기 | 설화·구전 |

`legend` 는 사실이 아닐 수 있다. 그래도 싣는 이유는 화면에 그대로 적는다 —
**"사실이 아닐 수 있으나, 이 지역이 무엇을 기억하려 했는지는 사실입니다."**
이 층위가 있어야 삼국유사·구비문학대계 같은 설화 자료를 정직하게 쓸 수 있다.

**출처를 적는 규칙**

1. 확인 가능한 **자료 단위**까지만 적는다. 확인하지 않은 쪽수·문서번호·판례번호는 적지 않는다.
2. `encyQuery` 나 `url` 이 있으면 화면에서 클릭 가능한 링크가 된다.
3. 출처를 밝히면 사람이 위험해지는 경우에만 `sourceNote` 로 그 사실 자체를 밝힌다.
   (예: 아웃팅 위험이 있는 커뮤니티 공간 — 구술에 근거하되 개인을 특정할 출처는 적지 않는다.)

### 3.5 `data/grandculture.json` — 향토문화전자대전 슬러그

한국향토문화전자대전은 **시군구 단위**로 쪼개져 있어 이 앱의 ② 단계와 그대로 맞물린다.

```
https://{slug}.grandculture.net/{slug}
  guro → 디지털구로문화대전 · asan → 디지털아산문화대전 · yongin → 디지털용인문화대전
```

230개 시군구 중 서비스 중인 곳은 121곳뿐이므로 **존재를 확인한 슬러그만 등록**하고,
없으면 링크를 만들지 않는다. 죽은 링크를 만드느니 링크가 없는 편이 낫다.

### 3.6 `data/motifs.json` — 전국 분포 모티프

전국에 변이형으로 퍼진 이야기·유물 유형. 두 가지 일을 한다.

**① 화면** — 장소에 `motifs: ["maesin-hyonyeo"]` 를 달면 상세 페이지에
「같은 이야기가 있는 곳」 블록이 붙어 다른 지역의 장소로 이어진다.
한 지역만 보던 사람이 그 이야기가 전국에 있다는 것을 알게 된다.

**② 기획** — `fills` 에 적힌 areaCode 를 보면 이 모티프 하나로 어느 빈칸을 메울 수 있는지 보인다.
`places` 는 실제로 캐시에 쓴 장소, `candidates` 는 아직 쓰지 않은 후보다.
시군구를 하나씩 훑는 것보다 모티프 하나를 잡아 지역별 사례를 뽑는 편이 빈칸을 훨씬 빨리 메운다.

```jsonc
{
  "id": "maesin-hyonyeo",
  "name": "몸을 판 딸",
  "lenses": ["people", "women", "disability"],
  "summary": "가난한 딸이 앞을 보지 못하는 부모를 먹이기 위해 자기 몸을 판다.",
  "reading": "…뒤집어 읽기. 이 유형 전체를 관통하는 한 문단",
  "distribution": "경주 빈녀양모, 곡성 관음사 연기설화, 판소리 심청가로 이어진다.",
  "fills": [35, 38, 37],
  "places":     [ { "areaCode": 35, "id": "gyeongju-binnyeo", "name": "…", "sigungu": "경주시" } ],
  "candidates": [ "전남 곡성 — 관음사 연기설화 원홍장" ],
  "sources": [ … ]
}
```

`places` 는 비정규화된 역색인이다. 장소를 추가하면 여기에도 넣어야 한다
(전체 캐시를 스캔하지 않고 한 파일만 읽어 교차 링크를 만들기 위한 의도적 중복).

### 3.7 `data/tour.json` — TourAPI 캐시 (손대지 않는 파일)

```jsonc
{
  "jinju-hyeongpyeong": {
    "matched": true,
    "contentid": "126508",
    "addr1": "경상남도 진주시 ...",
    "firstimage": "http://tong.visitkorea.or.kr/...",
    "overview": "관광공사 제공 개요",
    "mapx": 128.0812, "mapy": 35.1912,
    "fetchedAt": "2026-07-28"
  },
  "seoul-nagwon": { "matched": false, "fetchedAt": "2026-07-28" }
}
```

**손으로 쓴 이야기(`cache/`)와 API가 준 사실(`tour.json`)을 파일 단위로 분리한다.**
API 를 다시 돌려도 글이 날아가지 않고, 매칭 실패해도 앱이 깨지지 않는다.
`matched: false` 도 기록해서 재조회를 막는다.

## 6. 콘텐츠 원칙

1. **주인공을 먼저 쓴다.** 모든 장소 레코드의 필수 필드는 `voices` — "여기서 지워진 사람은 누구인가".
2. **출처 없는 글은 싣지 않는다.** `sources` 는 필수 필드다. 확인 가능한 자료 단위까지만 적고,
   확인하지 않은 쪽수·문서번호는 적지 않는다. 근거의 성격은 `evidence` 로 밝힌다.
3. **확실하지 않으면 쓰지 않는다.** 연도·인명·수치는 확인 가능한 것만. 불확실하면 문장에서 뺀다.
   설화는 `evidence: "legend"` 로 표시해 사실과 구분한다.
4. **모든 장소에 `ethics` 를 단다.** 추모지·거주지·유해 발굴지는 관광지가 아니다.
5. **원문으로 보낸다.** 우리 글은 요약이며, 전국 단위는 한국민족문화대백과사전,
   시군구 단위는 디지털○○문화대전으로 이어진다.
6. **소비하지 않는다.** 고통을 스펙터클로 만들지 않고, "포토스팟" 같은 표현을 쓰지 않는다.
7. **뒤집어 읽는다.** 전근대 유적은 대부분 지배층이 세운 기념물이다. "이것은 무엇을 기리는가"가
   아니라 **"이것이 서기 위해 누가 무엇을 감당했는가"**를 묻는다. 열녀문은 정절의 기념물이 아니라
   한 여자가 포기한 것의 기록이고, 효자비에 적힌 할고(割股)는 효가 아니라 가난의 기록이다.
   이 작업은 `lensNotes` 가 담당하며, 전근대 소재에서는 이것이 본문의 핵심이 된다.

### 서사 수집원

근현대 사건(항쟁·수용소·노동사)은 지역 편중이 심하다. 광주·제주·경남·서울은 넘치고
충북·강원·경북 내륙·전북은 거의 비어 있다. 전국에 균질하게 깔린 것은 설화·민속·불교 유적이므로,
**전근대 자료가 빈칸을 메우는 유일한 도구**다.

| 층 | 출처 | 쓰임 |
|---|---|---|
| 문헌 | 삼국유사(「감통」「효선」「피은」), 삼국사기 열전, 조선왕조실록 | 밀도 최고, 지역 편중 |
| 지역 | [한국향토문화전자대전](http://www.grandculture.net/korea) — 시군구 단위, 121개 지역 | 앱 구조와 1:1. 발굴·검증·링크 |
| 구전 | [한국구비문학대계](http://gubi.aks.ac.kr/) — 설화 56,386건 외 총 84,247건, 60여 시군 채록 | 빈칸 메우기 본진 |
| 유물 | 매향비, 고려 지방 거불(논산 관촉사·파주 용미리·안동 이천동), 경주 남산 마애불군 | 민중이 직접 남긴 물증 |

세 곳(백과사전·향토문화전자대전·구비문학대계)이 모두 한국학중앙연구원 자료라
출처 표기와 링크 체계가 하나로 정리된다.

**수집 순서는 모티프 우선.** 시군구를 하나씩 훑는 것보다, 전국에 변이형으로 분포하는 모티프를
하나 잡아 지역별 사례를 뽑는 편이 빈칸을 훨씬 빨리 메운다.

| 모티프 | 렌즈 | 특징 |
|---|---|---|
| 아기장수 | 민중 | 전국 분포. 지역마다 용마봉·장수바위 등 실제 지명이 붙어 있다 |
| 며느리바위 · 장자못 | 여성 | 시집살이 서사 |
| 당집 · 서낭당 · 무업 | 여성 · 민중 | 무당은 조선의 천민이자 대개 여성 |
| 매향비 · 미륵불 | 민중 | 향도 결사가 남긴 물증 |
| 열녀문 · 효자비 | 여성 · 민중 | 뒤집어 읽기의 대표 소재 |

렌즈는 5개로 고정한다 (17 × 5 = 85). 이주·정착민(화교, 귀환동포, 피란민 등) 소재는
별도 렌즈를 만들지 않고 `people`(민중) 안에서 다룬다 — 렌즈를 늘리면 캐시가 17건씩 늘어난다.
